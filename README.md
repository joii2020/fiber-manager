# Fiber Manager

Fiber Manager is a developer-focused browser extension for managing Fiber nodes.

This project is still in an early development stage. It is intended for developers who need to inspect and debug Fiber nodes from a browser-based management workspace. The extension can add nodes, refresh node status, display peers / channels / payments / graph data, and trigger selected Fiber RPC operations from the UI.

## Current Features

- WXT + React + TypeScript browser extension.
- Opens a `manager.html` workspace when the extension icon is clicked.
- Supports two node sources:
  - `RPC`: connects to a local or remote Fiber node through its JSON-RPC endpoint.
  - `WASM`: scans open browser pages and calls the Fiber WASM API mounted on the target page.
- Stores node configuration, node order, and active-node state in browser extension storage.
- Refreshes and displays `node_info`, `list_peers`, `list_channels`, `list_payments`, `graph_nodes`, and `graph_channels`.
- Includes UI entry points for selected peer, channel, payment, and invoice RPC operations.

## Requirements

- Node.js 20+ is recommended.
- pnpm 9+ is recommended.
- Chrome / Chromium or Firefox.
- A reachable Fiber node RPC endpoint, or an open browser page that has loaded Fiber WASM.

## Install Dependencies

```bash
pnpm install
```

After installation, WXT runs `prepare` to generate local type and runtime files.

## Local Development

Start the Chrome / Chromium development environment:

```bash
pnpm dev
```

Start the Firefox development environment:

```bash
pnpm dev:firefox
```

WXT starts the extension development environment and rebuilds when source files change. During development, click the Fiber Manager extension icon in the browser toolbar to open the management workspace.

## Type Check

```bash
pnpm compile
```

There is no unit test script configured yet. Run the type check before submitting changes.

## Build The Extension

Build for Chrome / Chromium:

```bash
pnpm build
```

Build for Firefox:

```bash
pnpm build:firefox
```

Build output is written under `dist/` in a browser-specific target directory, such as `dist/chrome-mv3` or `dist/firefox-mv2`. The exact directory name is generated by WXT for the selected target browser.

## Load In A Browser

### Chrome / Chromium

1. Run `pnpm build`.
2. Open `chrome://extensions`.
3. Enable Developer mode.
4. Click Load unpacked.
5. Select `dist/chrome-mv3`.
6. Click the extension icon to open Fiber Manager.

### Firefox

1. Run `pnpm build:firefox`.
2. Open `about:debugging#/runtime/this-firefox`.
3. Click Load Temporary Add-on.
4. Select `dist/firefox-mv2/manifest.json`.
5. Click the extension icon to open Fiber Manager.

## Add An RPC Node

1. Open the Fiber Manager workspace.
2. Click `+` above the node list in the left sidebar.
3. Select `RPC`.
4. Fill in the node name, network, and RPC endpoint.
   - The default endpoint is `http://127.0.0.1:8227`.
   - If the node requires authentication, fill in Auth token. Requests use `Authorization: Bearer <token>`.
5. Click Confirm.
6. Click the refresh button to load node status and read-only RPC data.

The RPC endpoint must allow `fetch` requests from the extension page. If the browser blocks requests because of CORS, allow the extension origin in the Fiber node or through a local proxy.

## Add A WASM Page Node

WASM mode connects to a Fiber WASM page that is already open in the browser.

1. Make sure the target page is open in a browser tab.
2. The page must have a Fiber database and expose the Fiber API on a global object.
3. Open Fiber Manager and click `+`.
4. Select `WASM`.
5. Fill in Mount point. The default value is `windows.fiber`.
6. Click the refresh icon to scan current browser pages.
7. Select the target page from Target page.
8. Click Confirm.

The scan checks whether the page has a Fiber-related IndexedDB store and whether the mount point exposes a callable API. Later RPC calls are executed by the extension background script in the target page's MAIN world.

## Early Version Limitations

- This is a developer preview, not a production wallet or end-user management panel.
- The UI and data model may still change. Node configuration stored in browser storage is not guaranteed to remain compatible across versions.
- RPC operation coverage is still incomplete. Validate behavior on devnet / testnet first.
- The extension does not define a popup, side panel, options page, or DevTools panel. The current entry point is the management workspace opened from the extension icon.
